# Why learners return

The intended return loop is: **find a relevant next step → save it → do a small piece of work → see progress → continue**. This is a product hypothesis, not a measured retention claim.

## Implemented support

- Source-backed learning picks saved under the learner's goal and chosen market.
- Today restores those choices, including Saved, Reading and Read states. Reading status is self-reported, not skill mastery.
- Weekly tasks, saved evidence, difficulty check-ins and plan adjustments make the next action practical.
- Goal history retains earlier work rather than making the learner restart.
- Preparation signals and lesson-referenced quizzes show what needs attention.
- Per-goal in-app focus reminders help a returning learner reorient; they are not background notifications.

## Response design

Learn uses compact provider cards, source references and a save action. Schools/opportunities retain location, access and eligibility details behind concise disclosure. The four-week view adds a visual roadmap with practical deliverables. Assessment distinguishes practice, evidence and formal eligibility. Actual source previews appear as provider searches finish; final answers are synthesized after retrieval. This is phased progress polling, not token-by-token response streaming.

Source presence is traceability, not independent fact verification. Maps remain regional context. Illustrations are labelled and optional for text-first users.

## Telegram roadmap

Telegram is a **future feature** for phone-based check-ins, reminders and next actions when learners do not have a computer. A polling adapter exists as an implementation scaffold; it is not part of the active learner promise or a verified integration. The responsive web interface remains available on phones now.

## What still needs evidence

Observe whether learners return to saved work after a few days, complete useful weekly tasks, recover after reporting difficulty and find resources relevant to non-computing goals. Measure these with informed consent and minimal personal data. Background notifications, calendar delivery and verified new-opportunity alerts are future work. A return visit should be earned by usefulness, not pressure or unsupported readiness claims.
